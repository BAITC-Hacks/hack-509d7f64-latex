The turn loop

One caller utterance = one pass through this loop. The loop is what the jury measures: which scenario, why, in how many milliseconds. Everything the critique asked for lands as a stage in it, so the page walks the loop top to bottom and marks, at each stage, what changes versus the code in backend/ today.

The LLM chooses every scenarioNo stage other than an LLM call ever assigns a scenario ID to an utterance. Retrieval narrows, Go verifies, but the choice is the model's.
Go verifies and executesThe model proposes; the executor checks the proposal against the catalog and the state before anything runs. Tools are Go functions the model cannot name.
Every stage emits a trace rowPath taken, candidates with scores, chosen + reason, alternatives, milliseconds. The supervisor panel is a rendering of the trace, not a separate feature.
No dead endsA timeout, a provider error or an unparseable answer drops one rung down a fallback ladder. The caller always gets a stored answer within the budget.

Shape of one turn

Stages

  1. Transcript arrives contract

    Layer 1 (STT + normalization) sends session_id, request_id, the raw normalized transcript, and a language hint (ru / kk / mixed). Idempotency on request_id stays exactly as today.

    Change vs. today

    Drop slots from the layer-1 contract. Today the normalizer may pre-extract slots that override the router's own extraction, so two components own the same values. The router extracts; layer 1 transcribes.

  2. Load session go ~0 ms

    Per-session lock, then the state: reply language, identity, the active frame (scenario, slots, next action index, pending preview), the stack of suspended frames, the queue of not-yet-started intents from a multi-intent turn, and the last 10 turns.

    Change vs. today

    None in shape. In-memory store stays for the hackathon; the half-started PostgreSQL lease layer (repository.go) is parked.

  3. Deterministic pre-router go ~1 ms

    Handles exactly two situations, both continuations of a scenario the LLM chose on an earlier turn, so no classification happens here:

    • The active frame is waiting for a slot and the utterance parses cleanly as that slot type per slots.json (phone ^\+7\d{10}$, 12-digit IIN, a date, an enum value). Fill the slot, jump straight to the executor.
    • A preview is pending and the utterance is an explicit yes/no from the catalog lexicon (Да / Подтверждаю / Иә / Нет / Жоқ…). Resolve it, jump to the executor.

    Anything with extra words (“да, но телефон другой”) fails the parse and continues to retrieval and the LLM.

    Change vs. today

    Today every turn pays a full LLM round-trip, including “910512300456”. Decision ownership becomes one rule: the LLM proposes, Go verifies. On the LLM path an irreversible action executes only if the model says is_continuation=true and the text contains an explicit affirmative; a bare regex never executes anything on its own.

  4. Retrieval shortlist go ~10 ms

    Score the utterance against every scenario's examples (ru + kk, ~7 per scenario), description and not_this_if conditions. Embeddings computed once at startup, or BM25 over the same text if we want zero external calls. Output: top-8 scenario IDs with scores, always joined by the active / suspended / queued scenario IDs and the three system intents.

    Two jobs: shrink the routing prompt from all 43 scenarios (~90 KB of JSON) to about ten, and produce a second, independent opinion that the uncertainty score can compare with the model's.

    Change vs. today

    New stage. Framing for the jury matters: retrieval feeds the LLM and never assigns a scenario. The trace shows the shortlist with scores next to the model's choice so this is visible, not claimed.

  5. Gate go ~0 ms

    Fast path when all of these hold, full path otherwise:

    • Top-1 retrieval score leads top-2 by at least τ_fast (calibrated, see the dev loop).
    • Top-1 is marked fast_path_eligible: true in scenarios.json. The dataset marks nine: SC18, SC23, SC24, SC26, SC31, SC33, SC34, SC36, SC37: documents, clinics, e-card, resend docs, payment methods, offices, app help, callback, human operator.
    • No active frame is waiting for input or holding a preview, and the stack is empty.
    Change vs. today

    The organizers shipped the fast_path_eligible flag; the current Scenario struct doesn't read it. This gate is where the “hybrid” in the case title lives.

  6. Route with an LLM llm fast ~350 ms · full ~900 ms

    Fast route. Small, low-latency model. Prompt: the utterance, three candidate scenarios (name, description, not_this_if), the system intents, the dataset date. No history (the gate guaranteed there is no live workflow). Output: one scenario, a one-line reason, reply language, slots.

    Full route. Main model. Prompt: the shortlist with examples and boundaries, slot definitions for those scenarios only, the compact state (active, suspended, queued, identity), the last 10 turns. Output: scenarios in spoken order, alternatives, reason, slots, is_continuation, needs_handoff. Strict JSON schema as today.

    Change vs. today

    Prompt shrinks roughly 5–8×. The per-scenario exceptions now baked into the system prompt (“small approved payout dispute is SC19, not SC17…”) move into the dataset's not_this_if, where the model reads them for the shortlisted scenarios; the prompt stops growing with every hard case we discover. Two models sit behind the existing Model interface, so the swap is configuration.

  7. Uncertainty score go ~0 ms

    A number computed in Go from observable signals, not read off the model:

    u = w1·(1 − margin_retrieval) + w2·[retrieval_top1 ≠ llm_top1] + w3·(1 − llm_confidence) ← one vote, not the verdict + w4·[a not_this_if condition of llm_top1 retrieved strongly]

    Thresholds τ_exec and τ_handoff come from sweeping u over the dev set and the sample dialogs, then get frozen and written into the README. Every component goes into the trace, so the supervisor sees why the robot doubted, not just that it did.

    Change vs. today

    Replaces the self-reported confidence with 0.75 / 0.45 cut-offs that were chosen, not measured. The brief's “where the model is unsure, it shows it” becomes evidence-based.

  8. Policy go ~0 ms

    • Confident → execute. Urgent scenarios (SC11 accident, SC15 illness abroad, SC38 fraud) first, the rest of a multi-intent turn queued, and the answer offers to come back to them.
    • Uncertain → clarification with two named options taken from the model's alternatives ∪ retrieval top-2. Skips the executor.
    • Hand off when: two consecutive uncertain turns, the model set needs_handoff for a scenario whose handoff.when applies, SC37 was requested, or the fallback ladder bottomed out. The packet carries transcript, chosen + alternatives, slots, queue. Skips the executor.
    Change vs. today

    Same decisions, driven by u instead of the raw model number.

  9. Executor go ~10 ms on mocks

    Identify if requires_identification → collect required slots in catalog order → run actions in catalog order. An irreversible action produces a preview and a pending frame; the next turn's explicit yes (verified as in stage 02) runs it. Corrections invalidate the preview. Tools are Go functions; the model cannot name a tool or a storage key.

    Change vs. today

    Frozen. This part already does more than the demo can show. No new frame semantics, no persistence work, no new mock rules.

  10. Response go llm 0 ms template · ~350 ms LLM

    Standard states are templated from the dataset, which already ships them: the slot question from slots.json → prompt, the scenario's responses.opening / closing with {price}-style placeholders filled from tool results, a fixed confirmation preview (“Оформляю ОГПО на … за … тенге. Подтверждаете?”). Deterministic, safe, instant, and TTS can start immediately.

    The LLM Respond call runs only for: clarification wording (turning two scenario names into a natural question), handoff messages, tool-error explanations, and free-form knowledge-base answers.

    Change vs. today

    Removes the second serial LLM round-trip from most turns. It is also a safety win: a template cannot claim a policy was issued when it wasn't.

  11. Trace + persist go

    The trace row for the turn: milliseconds per stage, path taken (bypass / fast / full), shortlist with scores, chosen scenario(s) with the model's reason, alternatives, uncertainty components, which not_this_if boundary was involved, fallback level used, actions with preview/execute mode. Store the turn under its request_id, unlock the session, return. The next turn re-enters at stage 01.

    Change vs. today

    Adds path, shortlist, uncertainty components and boundary evidence. The supervisor panel renders this row and nothing else.

Fallback ladder

Any model call that times out, errors, or returns JSON that fails validation drops one rung. Each rung is recorded in the trace as fallback_level.

  1. L0
    Primary model — the route chosen by the gate. Timeout 600 ms on the fast path, 1200 ms on the full path.
  2. L1
    Secondary model / provider, same prompt. A different vendor if we have one; otherwise the small model with the full prompt. One attempt.
  3. L2
    Retrieval-only, never execute. If the retrieval margin is high, answer with a clarification that names the top candidate (“Вы про оформление ОГПО, верно?”) and let the next turn confirm through the LLM. Nothing runs, nothing is promised.
  4. L3
    Hand off with context. The current behaviour on any error, but now the last resort instead of the first.

The outer loop: measure, then tune

The runtime loop above has four tunables (τ_fast, τ_exec, τ_handoff, the shortlist size). None of them is guessed; they come out of a dev harness that runs offline against the dataset.

1 · Single-turn accuracy

  • dev_utterances.json, all 104, empty session.
  • Per-path accuracy (bypass never applies here; fast vs. full).
  • Confusion pairs, e.g. SC17 ↔ SC19, SC11 ↔ SC12 ↔ SC13.
  • Reference scorer evaluate.py for the official breakdown.

2 · Multi-turn replay

  • dialogs_sample.json: 10 dialogs tagged scenario_switch, topic_switch, context_return, multi_intent, mixed_language, clarification, handoff, irreversible_action, language_switch.
  • Replay client turns through Engine.Process; compare the chosen scenario per turn and the status (awaiting_slot / awaiting_confirmation / handoff).
  • This is the only test of the things the case is actually about.

3 · Latency histograms

  • Per path, per stage, p50 / p95, from the same runs.
  • Prints the hybrid gain as a number: fast-path p50 vs. full-path p50. That number goes on the slide.

4 · Calibration

  • Sweep each τ over 1 + 2; pick the point that maximises accuracy subject to “no wrong execution of an irreversible action”.
  • Freeze, record in README, re-run before the demo.
